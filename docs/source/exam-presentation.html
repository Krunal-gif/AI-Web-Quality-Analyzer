01 · The problem

Website audits find problems but don't fix them

Tools like Lighthouse list issues. A developer still has to work out why each one matters, where it is in the code, and how to fix it safely.

🔍

Detect

Check a live site, a project folder or one file with 59 rules in 6 categories.

🧠

Explain

Every issue gets a built-in explanation. A local AI model adds a tailored one and drafts corrected code.

✅

Fix safely

The developer approves each fix. Only approved fixes are applied, and a re-scan checks that each one worked.

Key idea: the AI only ever proposes. Rules find the issues and the developer decides. The code never leaves the computer.

  • Screenshots are taken by a separate background process, and React polls for them.

06 · Step 1: Loading the target

SourceLoader: every input becomes a list of Documents

URL

Website

Downloads the page with curl and records the HTTP status, response time, headers and TLS details. A whole-site scan reads robots.txt and the sitemap first, then follows links up to the page limit.

Folder

Project

Walks the folder for .html .css .js .json .php .py files and skips node_modules, vendor, dist, .git and minified files.

File

Single file

One Document. The file's kind (html, css, js…) decides which rules run on it.

Document

Holds rel (path), kind, text (UTF-8) and a LineIndex that turns a byte offset into a line number quickly.

Site data

For websites: robots.txt, sitemap, speed, HTTPS, security headers, cookies and the site's own JS/CSS files. SiteProfile detects the platform, CDN and hosting.

07 · Step 2a: Parsing HTML

A custom parser that remembers exact positions

PHP's built-in DOMDocument discards source positions, but to fix code you must know exactly which bytes to replace. So HtmlParser.php builds its own small tree.

<a href="/"><img src="logo.png"></a>
             ^ start=13        ^ startEnd=31

Node {
  tag:      'img'
  attrs:    ['src' => 'logo.png']
  raw:      '<img src="logo.png">'
  start:    13     // byte offset of '<'
  startEnd: 31     // byte offset after '>'
  line:     9
}
  • Error-tolerant: real pages have unclosed tags. The parser recovers and records them as stray tags, which become issues.
  • Knows void elements (img, br…) and tags whose closing is optional (p, li…).
  • The regexes use possessive groups, so badly broken HTML can't make them backtrack for a very long time.
  • Text runs keep their offsets too, for content rules such as lorem ipsum and repeated words.

09 · The core data model

An Issue knows its exact region in the file

final class Issue {
  rule, category, severity, title, message
  file, line
  start, end      // byte region to replace
  original        // the exact text in that region
  ruleFix         // deterministic fix from the rule
  ai              // {why, fix, corrected, confidence}
  proposed        // the fix the user will approve
  proposedSource  // rule | ai | user
  status          // pending → approved → applied
  resolved        // set by the re-scan
}

Three kinds of region

start < end: replace this text.
start = end: insert here (e.g. a missing <meta viewport>).
start = −1: advisory only, with no automatic edit.

Fingerprint

rule + file + message with the numbers removed. It matches the same issue across two scans even when line numbers have moved. This is how the re-scan knows a fix worked.

10 · Scoring

A 0–100 score per category with exponential decay

score = 100 · e−penalty / 60

penalty = sum of the severity weights in that category

Severitycriticalhighmediumlowinfo
Weight2510520.5

Why not just 100 minus the points?

  • With a straight subtraction, a site with many small issues quickly hits 0 and stays there.
  • With decay, the first issues cost the most, the score never goes below 0, and each fix still moves it.
  • The overall score is the average of the 6 categories.

Example: 1 critical + 1 high = 35 points → 100 · e−35/60 ≈ 56.
Fix the critical one and the score rises to 100 · e−10/60 ≈ 85.

12 · Keeping AI output safe

validateFix(): every AI answer is checked before you see it

❌ Empty

No code was proposed, so the result is discarded and a message is shown.

❌ Unchanged

The model returned the original text, so it's discarded.

❌ Too large

More than 6× the flagged region (minimum 400 bytes), which means the model rewrote too much. Discarded.

❌ Wrong shape

The original was an HTML tag but the answer isn't one. Discarded.

✔ Re-indented

The original's leading and trailing whitespace is restored, and inserted lines are indented to match the file.

✔ Only a proposal

The status stays pending. Nothing is written until the user clicks Approve.

Markdown code fences (```) and marker tokens are removed first, because small models often add them.

13 · Background work

Slow AI calls don't freeze the app

A local model can take a minute for each issue. An HTTP request can't wait that long, so the work moves to a separate process.

1POST /aiAiController marks the issues aiPending and returns at once
›
2AiBatch::dispatchstarts php artisan webqa:ai-batch in the background with exec(… &)
›
3One issue at a timeCalls Ollama, then saves the result with Analysis::mutate()
›
4React pollsGET /api/analyses/{id} every 1.5 s until the batch is done

🔒 File lock: no lost updates

Analysis::mutate() takes an exclusive flock, loads the state, changes it and saves it. The worker and the user's clicks can't overwrite each other.

⏹ Cancel and offline

Before each issue the worker checks the cancel flag, and it stops early if Ollama is offline instead of failing 30 times.

15 · Step 5: Applying fixes

Fixer::applyToText() merges many edits into one file

  1. Sort the approved fixes by position.
  2. Check that the text at start..end still equals original. If it doesn't, the fix is marked failed.
  3. Group overlapping regions into clusters.
  4. Merge each cluster with a 3-way merge built on a Myers diff (Diff.php). For example, adding alt and rel to the same tag works.
  5. Edits that truly clash are marked conflict and are never applied blindly.
Default

Patch mode

Writes fixed/… copies and a unified changes.patch. Your files stay untouched. Live websites always use this mode.

Optional

In-place mode

Backs up each original to backup/ first. It refuses to write if the file changed on disk after the analysis.

17 · Security of the tool itself

A tool that writes files has to be careful

🛡 CSRF on every POST

The API lives in the web middleware group, not api.php, so a random website can't make your browser call it.

🏠 Localhost only

php artisan serve listens on 127.0.0.1. The README warns never to use 0.0.0.0, because the app has no login.

🧷 Safe writes

Patch mode is the default, and in-place mode makes backups. A file that changed on disk is refused. An analysis ID must match [\w.-]+, so no path tricks.

🔐 Privacy

Code goes only to the local Ollama. The security scan reads normal responses and probes nothing. Cookie values are never shown.

Appendix · Likely examiner questions

Questions and short answers (1/2)

Why use a local LLM instead of OpenAI?Privacy (client code never leaves the machine), no cost, no API key, and it works offline. The trade-off is speed, which is why the AI work runs in the background.
What if the AI is wrong?It only proposes. validateFix() discards bad answers, the user approves each fix, and the re-scan shows whether it really worked.
Why write your own HTML parser?DOMDocument loses byte positions. Fixes need the exact region to replace while keeping the rest of the file exactly as it was.
Why no database?An analysis is one document that is written by one user. JSON files plus a file lock are simpler, portable and easy to inspect.
How do two fixes on the same tag work?Overlapping regions are grouped, then merged with a 3-way merge built on a Myers diff. If they truly clash, it's a conflict and isn't applied.

Appendix · Likely examiner questions

Questions and short answers (2/2)

How is the score calculated?For each category: 100 · e^(−penalty/60), with weights critical 25, high 10, medium 5, low 2, info 0.5. The overall score is the average of the 6 categories.
How do you know a fix worked?The fixed text is analysed again. If the issue's fingerprint (rule + file + message without numbers) is gone, the fix is verified.
Why does the AI run in the background?A model call can take a minute. AiBatch starts a separate Artisan process, and React polls every 1.5 s.
Is it safe to point it at any website?It only reads public responses (pages, robots.txt, sitemap, headers) and never probes. Only scan sites you own or are allowed to test.
What would you add next?A login for team use, more frameworks (Vue, Blade templates), Lighthouse performance metrics, and scheduled scans that track the score over time.
