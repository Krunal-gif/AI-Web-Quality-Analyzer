Chapter 1

The project in one minute

WebQA checks a website or a code folder for problems, explains each problem in plain language, suggests a fix, and only changes anything after you approve it. Then it scans again to prove the fix worked. Three ideas: human in control, private (all local), proven (re-scan).

You give itExampleWhat happens
A website addresshttps://example.comDownloads the page, or the whole site from its sitemap, and checks it.
A project folder/home/you/my-siteChecks every supported file in the folder.
A single fileindex.htmlChecks just that file.

Supported files: .html .htm .css .js .mjs .cjs .json .php .py

How "59 rules read every page and file" works

Rule groupRuns onChecks
HtmlRules.phpEvery HTML pageSEO tags, accessibility, HTML structure, text content, unsafe links
CodeRules.phpEvery file (also scripts inside HTML)Syntax errors, JS/CSS quality, passwords and keys in code
SiteRules.phpOnce per website (URL only)HTTP errors, speed, robots.txt, sitemap, HTTPS, headers
  • Folders node_modules, vendor, dist, build, storage, .git and minified files are skipped.
  • At most 25 issues per rule per file are shown ("+N more like this"), so one noisy rule can't hide the rest.
  • If one file breaks a check, the other files are still checked.

Severity and score

LevelMeaningCosts
CriticalBroken or dangerous now (syntax error, leaked key)25
HighReal harm to users, Google or security10
MediumShould be fixed soon5
LowGood practice, small effect2
InfoA tip, not a problem0.5

Each of the six areas starts at 100 and drops as issues add up (100 × e−points/60): the first issues cost most and it never goes below 0. The overall score is the average of the six.

AI and fixes are kept safe

  • The AI sees one issue at a time and may only rewrite that exact spot. Broken or empty answers are thrown away.
  • AI runs in the background (php artisan webqa:ai-batch). Without Ollama every issue still has a built-in explanation.
  • Patch mode (default) leaves your files untouched and gives fixed copies plus changes.patch. Write mode backs up first and refuses if a file changed. Live websites always use patch mode.

Security headers and cookies

The 9 ★ header and cookie checks are read from the site's normal response; nothing is probed. They are fixed in the web server, CDN or app settings, not in the page's HTML. The Security report ↗ button shows only these findings.

lerd replaces php with a container version, so the browser can't reach the server. If which php shows .local/share/lerd, use /usr/bin/php8.4 instead of php to start the server.

Get the code

The repository is private. Ask Krunal to add you (Settings → Collaborators), accept the invite, then create a classic token: GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → tick repo. Use the token as the password.

Install, one command at a time

git clone https://github.com/Krunal-gif/AI-Web-Quality-Analyzer.git
cd AI-Web-Quality-Analyzer
composer install                 # PHP packages
npm install                      # JavaScript packages
cp .env.example .env             # settings file
php artisan key:generate         # secret key
npm run build                    # build the screen

# optional: local AI
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5-coder:3b     # then set OLLAMA_MODEL=qwen2.5-coder:3b in .env

Start it

/usr/bin/php8.4 artisan serve --no-reload     # or: php artisan serve --no-reload

Open http://127.0.0.1:8000. Keep the terminal open; Ctrl+C stops it. --no-reload gives 4 workers, which the app needs to analyse its own address.

Chapter 5

Using the app

  1. Enter a target (URL, folder or file). For a URL choose This page only or Whole site (sitemap), up to 50 pages. Click Analyse.
  2. Read the score: the ring is the overall score; the bars are the six areas.
  3. Open an issue to see the problem, why it matters, and the Before / After code.
  4. Ask the AI (optional): ✨ Explain & fix with AI for one issue, or the sidebar button for many.
  5. Decide: ✓ Approve, ✕ Reject or ✎ Edit each fix. Filter by severity, category or status.
  6. Apply: patch mode (safe) or write into your files (with backups).
  7. See the proof: a re-scan marks each fix ✓ verified or still detected, and shows score before → after.
  8. Share: final report, Share report (one .html file), security report, changes.patch or JSON.

The app has no login, so don't open it to the network.

When something fails

Read the first red line; later errors usually come from it. Check you're in the project folder (pwd). App errors also appear in storage/logs/laravel.log.

Questions you may be asked

How many checks are there?
59 rules in six areas: SEO 14, accessibility 8, HTML 9, content 4, code 9, security 15.
Why a local AI instead of ChatGPT?
Privacy and cost: code never leaves the computer, it's free and works offline. The tool also works without AI.
What if the AI is wrong?
It can only change the flagged spot, its answer is validated, a person approves every fix, and the re-scan shows if it worked.
Can it break my files?
Default patch mode doesn't touch them. Write mode backs up first and refuses if a file changed. Overlapping fixes are reported, never forced.
How is the score calculated?
Critical 25, high 10, medium 5, low 2, info 0.5 points. Each area starts at 100 and drops; the overall is the average of six areas.
Why no database, and why only a landing page on Vercel?
Each analysis is a folder of JSON files, so nothing to install. The app needs PHP, files and local AI, which Vercel doesn't offer.
Can it run before every release?
Yes: php artisan webqa:analyze ./site --fail-on=high fails the CI build if serious issues remain.
Limitations and next steps?
No login yet, AI slow without a graphics card, live sites only get patches, JavaScript-built content may be missed. Next: login, one-click PDF report, team server, more rules.
